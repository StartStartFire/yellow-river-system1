# 模型配置 Step 1：调度场景页面设计说明

## 1. 页面名称

```text
调度场景
```

## 2. 所属模块

```text
模型配置 / Step 1：调度场景
```

## 3. 页面定位

调度场景页面是模型配置流程重构后的**第一步**，以调度目的/业务为驱动，取代原先以模型数据为起点的流程。

本页面的核心任务是让用户先明确"本次要做什么调度"，即选择调度的场景类型和具体子场景，后续步骤（调度主体 → 模型数据 → 模型算法 → 场景配置 → 配置汇总）将基于此选择自动联动。

页面数据全部来自：

```text
src/mock/modelConfig.ts（新增 dispatchScenarioCategories）
```

页面风格延续全局深色写实科技风、蓝青色高亮、半透明面板、专业水利科研平台风格。

---

## 4. 页面开发目标

当前阶段需要实现：

```text
1. 显示顶部模型配置 6 步流程步骤条（当前高亮 Step 1）
2. 展示 3 个调度场景大类分区，横向排列
3. 每个分区包含：大图标 + 标题 + 描述文字
4. 每个分区内包含多个子选项（单选 radio）
5. 3 个分区互斥（只能选中一个分区）
6. 选中分区的视觉反馈（下划线高亮 + 选中态标记）
7. 子选项选中后自动关联调度目标（联动 Pinia Store）
8. 底部操作栏：取消 / 保存 / 下一步（与 Step 2~6 统一）
9. 点击"下一步"写入 Store 并跳转 Step 2
```

当前阶段不实现：

```text
1. 不调用后端接口
2. 不连接数据库
3. 不调用 MATLAB
4. 不做真实数据查询
```

## 6. 3 个调度场景大类

### 6.1 场景分区总览

| 分区ID | 名称 | 图标 | 场景说明 |
|--------|------|------|---------|
| multi-year | 多年的中长期调度 | 📅 日历 | 以年为单位的长期调度规划，统筹多目标水资源配置 |
| critical-period | 年内关键期调度 | 🌊 波浪 | 针对年内特定关键时期制定精细化调度方案 |
| realtime | 实时调度 | ⚡ 闪电 | 基于实时水情和预报信息的应急响应与精细调度 |

### 6.2 交互规则

```text
1. 3 个分区互斥：一次只能选中一个分区
2. 点击分区任意区域可选中该分区
3. 选中后分区显示下划线高亮和选中标记
4. 未选中分区保持默认透明状态
5. 每个卡片顶部显示独特的大图标（SVG 图标，非 emoji）
6. 图标下方显示卡片标题
7. 标题下方显示卡片描述文字（灰蓝色，较小字号）
8. 描述下方是子选项区域
```

### 6.3 默认状态

```text
默认不选中任何卡片（无默认选中项）
用户必须选择一个子场景才能进入下一步
```

## 7. 各卡片子选项设计

### 7.1 多年的中长期调度

只有一个子选项：

| 子选项ID | 名称 | 描述 | 关联调度目标 |
|---------|------|------|------------|
| multi-objective | 多目标优化调度 | 综合考虑防洪、发电、生态、供水等多目标协同优化 | flood-control, power-generation, ecology |

### 7.2 年内关键期调度

四个子选项（互斥，只能选一个）：

| 子选项ID | 名称 | 描述 | 关联调度目标 |
|---------|------|------|------------|
| flood | 防洪期 | 主汛期防洪调度，控制水库水位保障防洪安全 | flood-control |
| ice | 防凌期 | 凌汛期防凌调度，控制下泄流量防止冰塞冰坝 | ice-control |
| supply | 供水期 | 供水保障调度，保障城乡生活与工农业供水安全 | water-supply |
| sediment | 调水调沙 | 水沙联合调度，利用洪水过程输沙减淤 | sediment |

### 7.3 实时调度

四个子选项（互斥，只能选一个）：

| 子选项ID | 名称 | 描述 | 关联调度目标 |
|---------|------|------|------------|
| ice-sediment | 凌峰水沙调度 | 凌汛期水沙过程调控，协调防凌与输沙关系 | flood-control, sediment |
| cross-section | 断面输沙调度 | 控制断面输沙率，保障下游河道输沙效率 | sediment |
| reach | 区间冲淤调度 | 控制河段冲淤平衡，减少库区与河道淤积 | sediment |
| multi-energy | 多能互补 | 协调水电与风光等新能源，提高多能互补综合效益 | multi-energy |

### 7.4 子选项交互规则

```text
1. 每个卡片内的子选项使用 radio 单选样式
2. 点击子选项区域选中该子选项
3. 选中后 radio 圆点显示蓝色填充
4. 子选项选中时，其所在卡片自动变为选中态
5. 跨卡片切换时：点击另一个卡片的子选项，自动取消原卡片的选中
6. 子选项的关联调度目标自动写入 Pinia Store 的 selectedObjectives
```

## 8. 图标设计

### 8.1 卡片主图标（SVG）

三个大卡片顶部各显示一个独特的大图标（建议 48×48 或 56×56）：

**多年的中长期调度**：日历/时间图标
- 含义：代表跨年度的长期规划
- 风格：线框风格 + 蓝青色渐变

**年内关键期调度**：波浪/波动图标
- 含义：代表年内水位流量波动与关键时期
- 风格：线框风格 + 蓝青色渐变

**实时调度**：闪电/即时图标
- 含义：代表实时响应与应急调度
- 风格：线框风格 + 蓝青色渐变

### 8.2 子选项图标（可选）

子选项左侧可配合小图标增强语义区分：
- 防洪期 → 盾牌图标
- 防凌期 → 雪花/冰晶图标
- 供水期 → 水龙头/水滴图标
- 调水调沙 → 沙漏/颗粒图标
- 凌峰水沙 → 冰+水组合图标
- 断面输沙 → 截面/箭头图标
- 区间冲淤 → 平衡/天平图标
- 多能互补 → 同步/循环图标

当前阶段子选项可暂不加图标，仅保留 radio 单选样式。

## 9. 与 Pinia Store 的联动

### 9.1 Store 新增字段

在 `src/stores/modelConfig.ts` 中新增 Step 1 数据结构：

```ts
const dispatchScenario = ref({
  categoryId: '',       // 选中的大类ID: 'multi-year' | 'critical-period' | 'realtime'
  subOptionId: '',      // 选中的子选项ID
})
```

### 9.2 自动联动规则

选中子选项时，自动完成以下联动：

```text
1. 将 subOption.linkedObjectives 写入 basicConfig.selectedObjectives
2. 将 categoryId 和 subOptionId 写入 dispatchScenario
3. 标记 Step 1 为已完成
```

### 9.3 后续步骤影响

联动不是一次性写入，而是作为"调度场景选择"贯穿整个 6 步流程：

```text
Step 1 场景选择
    ↓ 影响调度目标类型 → Step 4 模型算法中的调度目标初始值
    ↓ 影响场景类型     → Step 5 场景配置中的默认参数
    ↓ 传递到 Step 6     → 配置摘要中显示"调度场景"信息
```

具体联动细节在后续步骤开发时逐步细化，当前 Step 1 阶段只实现到写入 Store 和联动调度目标。

## 10. 底部操作栏

底部使用公用组件 `ModelConfigFooter.vue`。

按钮配置：

```text
取消 / 保存 / 下一步
```

规则：

```text
取消按钮：
  1. 点击后弹出确认弹窗「确认取消当前操作？」
  2. 弹窗提供"继续编辑"和"确认取消"两个按钮
  3. 确认取消后清空 Step 1 的选中状态

保存按钮：
  1. 点击后弹出确认弹窗
  2. 确认后保存当前 Step 1 状态到 Pinia Store
  3. 弹出成功提示

下一步按钮：
  1. 如果未选中任何子选项，按钮置灰不可点击（或点击时提示"请先选择调度场景"）
  2. 选中后点击，执行：
     a. 将当前选择写入 Store
     b. 标记 Step 1 已完成
     c. 联动调度目标到 Store
     d. 跳转 Step 2（后续改为 /model-config/dispatch-subject）
  3. 当前阶段 Step 2 尚未开发，可暂跳转 /model-config/model-data 占位
```
