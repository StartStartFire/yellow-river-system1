## 一、模型定位

- **名称**：水沙统一调度模型与河道水文水动力演变、输沙造床的时空耦合模型
- **开发者**：西安理工大学
- **语言/环境**：Python 3.11，numpy / pandas / scipy / sklearn / matplotlib / openpyxl
- **性质**：**确定性仿真**（给定设计洪水重现期 → 一套确定结果），**非**多目标优化
- **输入**：设计洪水重现期（2 / 5 / 10 / 50 / 100 年）+ 水库初始水位（可选）
- **输出**：各断面洪水过程、刘家峡下泄—兰州断面流量迭代收敛过程、龙羊峡调度过程、包头—头道拐河段冲淤量

### 为什么要引入仿真模型（与原优化的区别）

| 维度 | 原模型（matlab-model） | 水沙耦合模型（river_model） |
|------|------------------------|------------------------------|
| 语言 | MATLAB | Python |
| 性质 | **多目标优化**（Pareto 解集） | **确定性仿真**（一套结果） |
| 求解 | NSGA-II / PAEM 遗传算法 | 马斯京根洪水演进 + **自迭代试算** |
| 评价 | NMF/PP/AHP-FUZZY 排名解集 | 无 evaluating 矩阵，**不参与评价** |
| 目标 | 缺水量/发电量/协同度 | 兰州断面流量入控制区间 + 冲淤量 |

> 原模型回答"**怎么调度最优**"，水沙模型回答"**这样调度后河道实际怎么响应、冲淤多少**"。两者并存互补。

## 二、模型理论

模型按**自然计算阶段**分为三个子模型：**M1 水沙实时调度**、**M2 河道水文水动力演进（洪水演进）**、**M3 输沙造床（河床变形）**，由耦合编排层 `C` 串成闭环。以下公式取自调研问卷（专题4）与模型源码，仅列原理，以代码为准。

### M1 水沙实时调度

**作用**：在流域梯级水库群中进行逐日调度推演，给定来水来沙与出库需求，求解各水库运行过程（下泄、水位、出力、弃水）。同时考虑断面输沙能力与下断面输水输沙量，定量描述水沙调控的输水输沙效果。

**基本约束（水量平衡原理与沙量平衡原理）**：

- 断面间水量平衡：
  `Q出(i) = Q出(i-1) + Q支流 − Q供水 + Q退水`

- 水库水量平衡：
  `W库(t+1) = W库(t) + Q入库·Δt − Q出库·Δt`

- 水库库容约束：`Vmin ≤ V ≤ Vmax`
- 出库流量约束：`Qmin ≤ Q出 ≤ Qmax`
- 出力约束：`N技术最小 ≤ N ≤ N装机`

**水电站出力**：通过 H-N-Q（水头-出力-流量）关系曲线查表，`N = f(H, Q发电)`。

**求解思路（自迭代模拟优化）**：模型不是遗传搜索，而是利用数学关系式描述系统参数与变量关系，通过计算机模拟实际变化。按**自适应控制原理**，在模拟优化模型中加入在线辨识结构——把模拟计算的输出结果经辨识后，**自动形成反馈修正量并反馈到输入端**，再按新输入重新模拟，引导结果自行趋向满足目标的解。这正是 M1→M2 耦合闭环的心脏。

### M2 河道水文水动力演进（洪水演进）

**作用**：以水库实时调度下泄流量为输入，沿河道逐断面演进，得各断面洪水过程。原理基于**连续性方程**与**动量守恒方程**：
- 连续性：`∂A/∂t + ∂Q/∂x = q旁入`
- 动量：`∂Q/∂t + ∂(αQ²/A)/∂x + gA·∂h/∂x + gA·Q|Q|/(C²R A²) = 0`

工程实现采用**非线性马斯京根法（Muskingum）** 推演：
```
Q下,2 = C0·Q上,2 + C1·Q上,1 + C2·Q下,1
```
其中系数 `C0/C1/C2` 由槽蓄系数 `k`、权重因子 `x` 及流量分级调整，且与流量大小非线性相关（`calculate_nonlinear_coefficients`）。各断面使用率定的演进参数（见 `mod_routing.py` 的 `DEFAULT_PARAMS`）。区间支流（民和、享堂等）来水在逐段演进中叠加。

**8 个演进断面（自上游至下游）**：兰州、下河沿、青铜峡、石嘴山、巴彦高勒、三湖河口、包头、头道拐。

### M3 输沙造床（河床变形冲淤）

**作用**：接收演进后的断面流量过程，基于泥沙平衡方程计算各子河段的冲淤。控制方程：
- 水流连续、水流动量、泥沙平衡（`∂(Qs)/∂x + ∂(A·S)/∂t = 0` 等的差分形式）

**计算要点**（涉及滩槽分配与河床变形）：
1. **滩槽分流**：当流量小于平滩流量，只算主槽输沙（恒定流 + 扣除沿程引水）；当流量大于平滩流量，洪水漫滩，用马斯京根公式进行沿程推演。
2. **滩槽输沙率分配**：入滩含沙量 `St` 与主槽含沙量 `Sc` 成比例（`St = K·Sc`，K 取 1.5~2）；河段淤积量由进出口断面输沙率之差扣除引沙求得。
3. **输沙率公式**：按汛期/非汛期/封冻期/桃汛期/水库排沙期五个时段分段拟合（封冻期、桃汛期与泄洪期、汛期与非汛期三套公式），常见形如 `Qs = a·Q^b`。
4. **冲淤厚度与床沙更新**：由泥沙平衡差分求得滩槽冲淤厚度，冲淤铺沙后形成新的断面形态（滩槽高差、平滩流量更新），进入下一计算时段——这就是"**造床**"的体现。

### C 耦合编排（自迭代闭环）

这是模型"耦合"的关键：**调度 → 演进 → 达标判断 → 修正 → 再调度**。

```
给定重现期洪水
  → M1 水沙调度（龙羊峡→刘家峡各库逐日推演，得刘家峡下泄过程）
  → M2 洪水演进（下泄 + 支流 → 8 断面洪水过程，特别是兰州断面）
  → 判断：兰州断面流量是否落入控制区间 [1850, 1900] m³/s？
      ├─ 是 → 收敛，进入 M3
      └─ 否 → 修正刘家峡下泄（adjust_liujiaxia_discharge）
             → 重算 M1/M2（自迭代）
  → M3 输沙造床（包头/头道拐流量 → 各河段冲淤，更新平滩流量）
```

每次迭代即一次"调度→演进→反馈"闭环，直至兰州断面流量满足控制目标。实测各重现期经 11~21 次迭代收敛（见下节验证）。

## 三、模型拆分粒度

### 拆分原则

- **只拆成"模块级"接口，不拆"过程数据级"**：8 个断面、滩地/主槽、子河段等属于**过程数据**（M2/M3 返回 dict），不要为每个断面单独建接口，避免过度拆分。
- 每个子模块可**独立调用**、能**暴露过程数据**（服务化、透明化）。

### 拆分结果

| 模块 | 源码位置 | 作用 | 是否可独立 |
|------|----------|------|-----------|
| **M1 水沙调度** | `coupledModel.py` `run_real_time_scheduling` | 逐日推演各库，输出下泄/水位/出力/弃水 | ⚠️ 全局状态重（不易独立） |
| **M2 洪水演进** | `mod_routing.py` `run_routing` | 上断面下泄 + 支流 → 8 断面洪水过程 | ✅ 纯 numpy |
| **M3 输沙造床** | `mod_sediment.py` `run_sediment` | 包头/头道拐 → 各河段冲淤 + 平滩流量更新 | ✅ 较易 |
| **C 耦合编排** | `run_model_service.py` | 调度→演进→达标→修正→再调度（自迭代） | 服务入口 |

### 模块接口（已完成）

- M2：`run_routing(liujiaxia_outflow, mh_flow, xt_flow, params) -> dict`
- M3：`run_sediment(Q_baotou, Q_toudaoguai, base_xlsx, save_output, label) -> dict`
- C：`run_model_service.py`（命令行入口，含进度上报与结果落盘）

> 详细接口定义与部署步骤见 [water-sediment-coupling-model-integration.md](water-sediment-coupling-model-integration.md) §2、§3。

## 四、集成到系统的意义与解决的问题

### 4.1 解决什么问题

原系统（`matlab-model`）只回答"**怎么调度最优**"——NSGA-II/PAEM 搜索出一组非支配的 Pareto 调度方案，并给出缺水量/发电量/协同度等目标值。但它**从不回答"方案落地后河道到底会发生什么"**，即：

- 这样调度后，给定重现期洪水沿河道如何演进？（各断面洪水过程）
- 龙羊峡/刘家峡的实际调蓄过程、下泄过程是否满足下游防洪/防凌控制？
- 最终下游河段（尤其包头—头道拐）**冲淤多少、河床如何演变**？

这些是**水沙维度**的物理响应，是原优化模型完全无法计算的。水沙耦合模型正好补齐这一环，实现"**调度方案的效果验证**"。

### 4.2 部署意义

1. **补足"水沙过程仿真"能力**：系统从"多目标优化求解器"扩展为"**优化 + 水沙过程仿真**"的综合平台——既知道"该怎样调度"，也知道"这样调度后河道怎么响应"。
2. **满足调研需求（专题4 案例库）**：问卷明确要求展示 2/5/10/50/100 年一遇洪水来临时反馈修正刘家峡下泄迭代过程、各断面最终洪水过程、包头-头道拐冲淤过程——这正是本模型产出。
3. **过程透明**：新增一条"洪水情景仿真 + 过程透明"链路，与原有"多目标优化 + 评价决策"并存，把水沙计算过程（迭代收敛/断面洪水/调度/冲淤）透明展示给用户。
4. **模型复用与拆分**：通过模块化拆分，M2/M3 可独立调用与二次开发；服务化后可通过 HTTP/子进程被系统调度。

## 五、边界与注意事项

- **模型定位差异**：水沙是**确定性仿真**，无 `evaluating` 矩阵 → 不参与 NMF/PP/AHP-FUZZY 评价；评价决策页对水沙任务已做优雅降级（"决策分析"Tab 禁用）。
- **数据性质**：输出是**物理仿真结果**（真实模型对实测数据的复现），非实测观测值；与实测断面的精度对比属模型率定范畴，不在集成范围。
- **运行时**：单次约 160 秒（反馈迭代数 + Excel 读写）；后端以子进程隔离运行，MATLAB 未就绪不影响水沙模型。
- **前端展示**：断面洪水、迭代收敛、龙羊峡调度、冲淤 4 类图，通过 `/cb → WS` 实时推送，`/process` 补拉。
